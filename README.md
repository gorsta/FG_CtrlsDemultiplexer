
# Hid controls demultiplexer for FlightGear

Summary
-------
Hid controls demultiplexer, cdmux for short, lets one group of hid buttons bind to a larger number of simulator properties. A rotary encoder with button press, for example, has three switches: ccw rotation, cw rotation and button press. Events from these three switches can be de-multiplexed with cdmux to act on individual members of a (larger) group of sim/cockpit controls, using e.g. ccw/cw to select the simulator control to act on and button press to toggle the control, turning on/off e.g. left landing light, right landing light, taxi light, strobe lights, Beacon and navigation lights. The group of hid buttons can be as large as desired and, at the smallest having only one button. 


A little more detail
--------------------
Button/switch operations can be characterized as button down, button up, short press and long press. This combined with the button identifier letter(s), e.g. 'x' constitutes the events x_down, x_up, x_short and x_long that can be generated by operating this button. Note that a button operation will generate one of these two sequences of events:  

x_down, x_short, x_up  
or  
x_down, x_long, x_up  

Each group of buttons/switches is setup with its own demultiplexer which can handle demultiplexing into several groups of sim/cockpit controls.

The demultiplexer is configured with actions for selecting one of several groups, and selecting one of several sim/cockpit controls within the group. 

Each event from the group of switches is passed to the demultiplexer identified by the name of the group (e.g. 'EN1' for encoder one). The event is checked against actions for selecting group, actions for selecting sim/cockpit control within the group and actions for the selected sim/cockpit control. If the event matches, the action is performed, a corresponding message is displayed as a pop up in the simulator window and search for (further) matches is terminated. Any event can only trigger one action.


Setting up the demultiplexer
----------------------------
The demultiplexer is setup and configured in a few steps:

- Put cdmux.nas and dmuxmatchmodel.nas in $FG_HOME/Input/Joysticks.

- Put the xml file(s) for your joystick(s) to be used with the demultiplexer in $FG_HOME/Input/Joysticks.

- Create a directory structure $FG_HOME/Input/Joysticks/demux with a subdirectory for each joystick to be used with the demultiplexer.

- Create demultiplexer configuration file(s) in the joystick subdirectories, one for each joystick/aircraft combination.

- Create a modifier (shift) property (if not arleady existing) and bind this to a button on at least one of the joystick(s).  
  Update *var shiftPropertyPath* in cdmux.nas with the correct property path.

- Copy nasal script code and set button bindings in the xml files for joystick(s) to be used with the demultiplexer.  

**WARNING:** If you use the in-sim joystick configuration GUI, it will
overwrite your XML configuration without warning. Therefore, it is good practice to keep backup copies of your xml files (indeed of all files in $FG_HOME/Input/) for safety.

The demultiplexer setup directory structure:  
$FG_HOME/Input/Joysticks  

     └── Joysticks  
         ├── VKB_Gunfighter_MCG_Ultimate.xml  (joystick xml file)  
         ├── VKB_S-TECS_STEM.xml              (joystick xml file)

         ├── cdmux.nas                        (demultiplexer)  
         ├── dmuxmatchmodel.nas               (aircraft demux match)  
         ├── demux                            (demux config files)

         │       │  
         │       ├── dc-3.nas                       (demux DC-3 config)  
         │       └── default.nas                    (demux default config)  
         │



The demux config file
---------------------
The configuration is specified in a .nas file which, when loaded, is parsed as a nasal script file.

Each group of hid controls must be identified by a string element in the hidCtrls vector:  

    var hidCtrls = ["EN1", "EN2", "SW12"];

For each string element in the hidCtrls vector there must be defined a "buttons" entry (a hash) and an "items" entry (a vector). Example for "EN2" follows.  
The "buttons" entry maps hid switch number(s) to button identifier letter(s):  

    var EN2buttons = {
        28: "aa",
        29: "bb",
        31: "cc",
        };

The "items" entry lists groups of sim/cockpit controls:  

    var EN2items = ["NavLights"];  

Finally, for each element in the "items" vector must be defined a vector of cockpit/sim items (hash(es)) containing:

- name: string with the name of the element

- one or several event/action pairs

Optionally, property path(s) can be defined:

- prop: property path(s) as string or vector of strings  


In this example there is only the item "NavLights" with two cockpit items:  

    var NavLights = [
        {name	: "L landing light", 
        cc_short: ["toggle", ["Left landing light", "/controls/lighting/landing-lights"]],
        }, 
        {name	: "R landing light", 
        cc_short: ["toggle", ["Right landing light", "/controls/lighting/taxi-light"]],
        }, 
        ];

Event/action pairs
------------------
An event/action pair is described as a key/value pair with an event as the
key and the value is a vector with an action and its parameters (in a vector), 
e.g.:  

    event: ["action", ["popup", "target", . . ]]
                       -- action parameters --
                       
            "popup"     string that will be displayed in sim as a popup 
                        message after the action was performed. 
        
            "target"   the target property path. Can also be a vector of
                       property paths. The property value(s) may be 
                       displayed in the popup message. 
        
Both "popup" and "target" may be omitted from the action parameters.  
If "popup" is omitted, the name string is used for the message.  
If "target" is omitted, the first property path(s) of prop will be used 
as target for the action.

The examples below are all valid event/action pairs:

    cc_short: ["toggle", ["Left landing light ", "/controls/lighting/landing-lights"]]
        
    cc_short: ["toggle", ["/controls/lighting/landing-lights"]]
        
    cc_short: ["toggle", ["Left landing light "]]
        
    cc_short: ["toggle", []]
        
    cc_short: ["toggle"]
        
The last three requires that prop was defined:  

    prop    : "/controls/lighting/landing-lights"  
    

Actions
-------
There are five actions available:  

    "popup"     Display a popup message in sim.
    Parameters: "popup", "target"

    "toggle"    Toggle a property. 
                Display a popup message in sim.
    Parameters: "popup", "target"

    "swap"      Swap the values of two properties. 
                Display a popup message in sim.
    Parameters: "popup", vector of "target"(s)

    "adjust"    Adjust a property value within min max bounds. 
                Wrap around the value or just keep it within bounds.
                Display a popup message in sim.
    Parameters: "popup", "target", step, minval, maxval, wrap 
                 Defaults for the last four parameters are 1, 0, 1, 0.  
    
With proper values for step, minval and maxval, adjust can be used to 
    increase/decrease a property value, set a property to a specific value, 
    and even act as a multi postition rotary (e.g. tank selector or magnetos switch). 

    "script"    Run script.  
                Display a popup message in sim.
    Parameters: "popup", "target", function 
                function is a nasal script to run.  
                
The in sim popup message can be suppressed by providing an empty string ("") as popup. 
                


Reserved (already in use) events
--------------------------------
For demultiplexing there must be some button operations for selecting what item(s) to act on. The following button IDs and operations are reserved:  

    aa_down         set skip = !shift
    bb_down         set skip = !shift
    cc_down         set skip = true
    cc_up           set skip = false

With these event/action pairs and the skip flag the following functionality is provided:  

    shift  +  aa_short    select previous group of items
    shift  +  bb_short    select next group of items
    
              aa_short    select previous item within the group
              bb_short    select next item within the group
    
    cc_down + aa_short    perform the action of the aa_short event
    cc_down + bb_short    perform the action of the bb_short event

E.g. let the item be the altimeter and the hidCtrl be an encoder knob which when turned ccw sends pulses on aa, when turned cw sends pulses on bb and the knob pushbutton is connected to cc. The altimeter would then be selected by turning the encoder knob. When selected, the altimeter could be adjusted by holding down and turning the encoder knob.


The popup message
-----------------
A popup message is displayed in sim after selecting an item. The items name string is used for the message.

A popup message may be displayed in sinm after performing an action. The message is composed according to the following rules.

When no message string is given in the params vector:  

> *The items name string is used for the popup message*

Message string is empty, "": 

> *No popup message is displayed*
    
Message string does not end with a space:  

> *Only the message string is displayed after the action*

Message string ends with a space: 

> *The message string with standard formatted property value is displayed after the action*

Message string contains the % (formatting) character:  

> *Formatting embedded in the message string is applied to the property value. Message string with the formatted property value inserted is displayed after the action.* 

For action "script" there would generally be no obvious property associated. Therefore, only the message string is displayed.

In some cases enumeration of strings provide for a better display message than the actual integer value of the property. For this purpose a string may consist of substrings separated by delimiters, ";",  to provide enumeration of specific substrings for each integer value of the property. E.g.: 

    "Tanks OFF;Tank RIGHT;Tanks BOTH;Tank LEFT" for the values 0, 1, 2, 3 of the property for the fuel tank selector. 

The first substring may be a label separated from the rest with a ":" as delimiter. E.g.: 

    "Tanks:OFF;RIGHT;BOTH;LEFT". This would produce the enumerator strings "Tanks: OFF", "Tanks: RIGHT", "Tanks: BOTH", "Tanks: LEFT" selectable as message string. 

The selected enumerator string is subject to the same preparation for display as any message string, as described above.


The joystick xml file
---------------------
Edit the nasal script section and button bindings in the xml file of each of the joystick(s) to be used with the demultiplexer.

Copy to the nasal script section:

- if one is not already in place, the section for setting up a modifier (shift) property

- the demultiplexer section

Example binding for a modifier (shift) button:  

    <!-- Shift button :: stick button left side -->
    <button n="6">
      <desc>Joystick Shift Key</desc>
      <binding>
       <command>nasal</command>
       <script>setprop(modPath, 1);</script>
      </binding>
      <mod-up><binding>
       <command>nasal</command>
       <script>setprop(modPath, 0);</script>
       </binding></mod-up>
    </button>

Example binding for connecting button 28 to the demultiplexer:  

    <button n="28">
      <desc>Button description (optional)</desc>
      <binding>
       <command>nasal</command>
       <script>bdn(28);</script>
      </binding>
      <mod-up><binding>
        <command>nasal</command>
        <script>bup(28);</script>
       </binding></mod-up>
    </button>
